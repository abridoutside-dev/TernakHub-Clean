TernakHub - Project Rules

Vision

Build the most trusted livestock ecosystem that is simple, evidence-based, lightweight, and accessible for everyone.

---

Core Principles

1. Farmers and buyers are equally important.
2. Trust is built from evidence, not authority.
3. The system must never fabricate data.
4. Verification should be system-based whenever possible.
5. Simplicity is preferred over complexity.
6. Mobile-first experience is mandatory.
7. Performance is more important than visual effects.
8. The application must remain lightweight for low-end Android devices.
9. Every feature must provide real value.
10. Long-term maintainability is more important than short-term speed.

---

Product Principles

- Mobile First
- Progressive Web App (PWA)
- Responsive like a native application
- Offline First whenever technically possible
- Fast loading
- Accessible
- Minimal memory usage
- Clean and modern interface

---

Development Principles

- GitHub is the single source of truth.
- Replit is used only for development.
- Every completed change must be committed to GitHub.
- Never generate fake or placeholder business logic without explicit instruction.
- Follow modular architecture.
- Keep components reusable.
- Write clean, readable code.
- Avoid unnecessary dependencies.

---

AI Rules

When implementing features:

- Never redesign the application without instruction.
- Never change business rules.
- Never rename modules without approval.
- Never remove existing features unless instructed.
- Ask for clarification instead of making assumptions.
- Prioritize maintainability and performance.

---

General Rule

If there is a conflict between convenience and the Project Rules, always follow the Project Rules.
